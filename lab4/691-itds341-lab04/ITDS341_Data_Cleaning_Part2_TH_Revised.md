# ค่าผิดปกติคืออะไร

ค่าผิดปกติ (Outlier) คือค่าที่แตกต่างจากข้อมูลส่วนใหญ่อย่างเห็นได้ชัด

ตัวอย่าง

```text
3, 6, 1, 4, 5, 3, 2, 1, 367
```

ค่า `367` แตกต่างจากค่าอื่นอย่างมาก จึงควรถูกระบุให้ตรวจสอบเพิ่มเติม

อย่างไรก็ตาม วิธีการทางสถิติทำได้เพียงระบุ **ค่าที่อาจผิดปกติ (Potential Outlier)** เท่านั้น ยังไม่สามารถสรุปได้ทันทีว่าค่านั้นผิดหรือควรถูกลบ

# ค่าที่แตกต่างอาจเกิดจากหลายสาเหตุ

| สาเหตุ | ตัวอย่าง | แนวทางเบื้องต้น |
|---|---|---|
| บันทึกข้อมูลผิด | คะแนนสอบ 78 จากคะแนนเต็ม 35 | ตรวจสอบและแก้ไขจากแหล่งข้อมูลต้นทาง |
| ระบบหรืออุปกรณ์ผิดพลาด | เซนเซอร์วัดอุณหภูมิได้ 900°C | ตรวจสอบอุปกรณ์หรือบันทึกเหตุการณ์ |
| หน่วยวัดไม่ตรงกัน | บางระเบียนใช้กิโลกรัม บางระเบียนใช้ปอนด์ | แปลงให้อยู่ในหน่วยเดียวกัน |

# เหตุใดจึงต้องตรวจสอบค่าผิดปกติ

ค่าผิดปกติอาจส่งผลต่อ

- ค่าสถิติสรุป เช่น ค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐาน
ค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐาน
- รูปแบบความสัมพันธ์ระหว่างตัวแปร
- ผลลัพธ์ของแบบจำลอง เช่น การพยากรณ์ การจำแนกประเภท และการจัดกลุ่มข้อมูล
- การปรับสเกลข้อมูล
- การตีความและการตัดสินใจทางธุรกิจ

แต่ผลกระทบขึ้นอยู่กับ

- วิธีวิเคราะห์หรืออัลกอริทึมที่เลือกใช้
- จำนวนและความรุนแรงของค่าผิดปกติ
- ลักษณะการแจกแจงของข้อมูล
- ว่าค่าดังกล่าวเป็นข้อผิดพลาดหรือข้อมูลจริง

ดังนั้น เป้าหมายไม่ใช่การลบค่าที่แตกต่างทั้งหมด แต่คือการ **ตรวจหา ตรวจสอบ และเลือกวิธีจัดการอย่างมีเหตุผล**

# ขั้นตอนการตรวจสอบค่าผิดปกติ

# เริ่มจากกฎของข้อมูล (Domain Rules)

ก่อนใช้วิธีทางสถิติ ควรตรวจสอบค่ากับกฎที่ทราบอยู่แล้ว

ตัวอย่างชุดข้อมูลคะแนน

| ตัวแปร | ช่วงค่าที่เป็นไปได้ |
|---|---:|
| Homework | 0–30 |
| Lab | 0–15 |
| Quiz | 0–25 |
| Midterm | 0–25 |
| Final | 0–35 |

```python
# Create a sample student-score DataFrame
df = pd.DataFrame({
    "HW":      [18, 22, 25, 29, 14, 31, 20, 10],
    "Lab":     [12, 13, 14, 15, 10, 11, -2, 8],
    "Quiz":    [17, 20, 22, 25, 14, 19, 18, 28],
    "Midterm": [16, 18, 21, 25, 12, 17, -5, 19],
    "Final":   [24, 27, 30, 35, 20, 78, 25, 29]
})

display(df)

score_limits = {
    "HW": (0, 30),
    "Lab": (0, 15),
    "Quiz": (0, 25),
    "Midterm": (0, 25),
    "Final": (0, 35)
}

for column, (lower, upper) in score_limits.items():
    invalid = df.loc[~df[column].between(lower, upper)]

    print(f"\n{column}: valid range = {lower}–{upper}")
    display(invalid)
```

<!-- ![alt text](assets/student_invalid_scores.png) -->

ค่าที่ตรวจพบจะประกอบด้วย:

| Column | Invalid Value | เหตุผล |
|---|---:|---|
| HW | 31 | คะแนนเต็ม 30 |
| Lab | -2 | คะแนนต้องไม่ต่ำกว่า 0 |
| Quiz | 28 | คะแนนเต็ม 25 |
| Midterm | -5 | คะแนนต้องไม่ต่ำกว่า 0 |

Domain Rules ช่วยตรวจจับ **ค่าที่ผิดเงื่อนไขของข้อมูล** หรือ **ค่าที่เป็นไปไม่ได้** เช่น คะแนน Final เท่ากับ 78 ทั้งที่คะแนนเต็มคือ 35 

อย่างไรก็ตาม ค่าที่ไม่ผิดเงื่อนไข เช่น นักศึกษาได้ 35 คะแนนเต็มในการสอบ Final อาจยังแตกต่างจากคะแนนของนักศึกษาส่วนใหญ่ได้

# ทำความเข้าใจ Box Plot

Box Plot สรุปการแจกแจงด้วยค่ามัธยฐานและควอไทล์

- `Q1`: ควอไทล์ที่ 1 หรือเปอร์เซ็นไทล์ที่ 25
- `Median`: ค่ามัธยฐาน หรือเปอร์เซ็นไทล์ที่ 50
- `Q3`: ควอไทล์ที่ 3 หรือเปอร์เซ็นไทล์ที่ 75
- `IQR = Q3 - Q1`: พิสัยระหว่างควอไทล์
- Lower fence: `Q1 - 1.5 × IQR`
- Upper fence: `Q3 + 1.5 × IQR`

ปลายเส้น whisker โดยทั่วไปแสดงค่าต่ำสุดและสูงสุดที่ยังอยู่ภายใน fence ไม่จำเป็นต้องเป็นค่าต่ำสุดและสูงสุดของข้อมูลทั้งหมด

ค่าที่อยู่นอก whisker คือ **ค่าที่อาจผิดปกติ** ไม่ใช่ค่าที่ต้องลบโดยอัตโนมัติ

![องค์ประกอบของ Box Plot](assets/boxplot_components.png)

> **หมายเหตุเกี่ยวกับภาพ:** คำว่า “Minimum” และ “Maximum” ในภาพหมายถึงปลาย whisker ตามเกณฑ์ `1.5 × IQR` ไม่จำเป็นต้องเป็นค่าต่ำสุดและสูงสุดของข้อมูลทั้งหมด

ภาพนี้แสดงความสัมพันธ์ระหว่าง Box Plot และ Normal Distribution

![Box Plot, IQR และการแจกแจงปกติ](assets/boxplot_normal_distribution.png)

- กล่องของ Box Plot ครอบคลุมข้อมูลส่วนกลาง 50% ตั้งแต่ Q1 ถึง Q3
- เส้นภายในกล่องแสดง Median
- IQR คือระยะระหว่าง Q1 และ Q3 โดยคำนวณจาก `IQR = Q3 - Q1`
- เกณฑ์ที่ใช้ระบุ Potential Outliers คือค่าที่ต่ำกว่า `Q1 - 1.5 × IQR` 
  หรือสูงกว่า `Q3 + 1.5 × IQR`

สำหรับข้อมูลที่มี Normal Distribution:

- Q1 อยู่ที่ประมาณ `-0.6745σ`
- Q3 อยู่ที่ประมาณ `+0.6745σ`
- IQR จึงมีค่าประมาณ `1.349σ`
- Lower Fence และ Upper Fence จะอยู่ที่ประมาณ `-2.698σ` และ `+2.698σ`
- ข้อมูลที่อยู่นอก Fence มีประมาณ 0.7% หรือประมาณ 0.35% ในแต่ละด้าน

อย่างไรก็ตาม IQR Method ไม่ได้กำหนดให้ข้อมูลต้องมี Normal Distribution  
กราฟโค้งด้านล่างใช้เพียงเพื่อแสดงตำแหน่งของ Q1, Q3 และ IQR เมื่อข้อมูลมีการแจกแจงแบบปกติเท่านั้น

ถ้าข้อมูลเป็น Normal Distribution เกณฑ์ IQR จะได้ Fence ที่ประมาณ ±2.698σ ซึ่งใกล้กับเกณฑ์ ±3σ ของ Z-score แต่ทั้งสองวิธีคำนวณจากคนละหลักการ และอาจให้ผลต่างกันเมื่อข้อมูลมีการแจกแจงแบบเบ้

# ตรวจหาค่าที่อาจผิดปกติด้วย IQR

```python
q1 = df["Final"].quantile(0.25)
q3 = df["Final"].quantile(0.75)
iqr = q3 - q1

lower_fence = q1 - 1.5 * iqr
upper_fence = q3 + 1.5 * iqr

potential_outliers = df.loc[
    (df["Final"] < lower_fence) |
    (df["Final"] > upper_fence)
]

print(lower_fence, upper_fence)
print(potential_outliers)
```

ข้อดี

- ไม่พึ่งค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐาน
- ทนต่อค่าที่สูงหรือต่ำมากได้ดีกว่า Z-score
- ใช้งานและอธิบายได้ง่าย

ข้อควรระวัง

- เป็นเกณฑ์เชิงสถิติ ไม่ใช่กฎยืนยันว่าข้อมูลผิด
- ในข้อมูลที่เบ้มาก อาจระบุค่าที่ถูกต้องจำนวนมากว่าเป็นค่าที่อาจผิดปกติ

# ตรวจหาค่าที่อาจผิดปกติด้วย Z-score

Z-score แสดงว่าค่าหนึ่งอยู่สูงหรือต่ำกว่าค่าเฉลี่ยกี่ส่วนเบี่ยงเบนมาตรฐาน

$$
z = \frac{x-\mu}{\sigma}
$$

โดยที่

- $x$ คือค่าที่ต้องการตรวจสอบ
- $\mu$ คือค่าเฉลี่ยของข้อมูล
- $\sigma$ คือส่วนเบี่ยงเบนมาตรฐาน
- $z$ คือระยะห่างจากค่าเฉลี่ยในหน่วยของส่วนเบี่ยงเบนมาตรฐาน

การแปลผล:

- $z = 0$ หมายถึง ค่านั้นเท่ากับค่าเฉลี่ย
- $z > 0$ หมายถึง ค่านั้นสูงกว่าค่าเฉลี่ย
- $z < 0$ หมายถึง ค่านั้นต่ำกว่าค่าเฉลี่ย
- ยิ่ง $|z|$ มีค่ามาก แสดงว่าค่านั้นยิ่งอยู่ห่างจากข้อมูลส่วนใหญ่

เกณฑ์ที่ใช้กันบ่อยคือ ระบุค่าที่มี $|z| \geq 3$ ให้ตรวจสอบเพิ่มเติม

### ตัวอย่าง

กำหนดให้คะแนนมีค่าเฉลี่ย $\mu = 25$ และส่วนเบี่ยงเบนมาตรฐาน $\sigma = 5$  
หากนักศึกษาคนหนึ่งได้คะแนน $x = 40$

$$
z = \frac{40-25}{5} = 3
$$

ดังนั้น คะแนน 40 อยู่สูงกว่าค่าเฉลี่ย 3 เท่าของส่วนเบี่ยงเบนมาตรฐาน  
เมื่อใช้เกณฑ์ $|z| \geq 3$ คะแนนนี้จะถูกระบุเป็น Potential Outlier


```python
mean = df["Final"].mean()
std = df["Final"].std()

z_score = (df["Final"] - mean) / std
potential_outliers = df.loc[z_score.abs() > 3]

print(potential_outliers)
```

> เกณฑ์ ±3 เหมาะกับการคัดกรองข้อมูลที่มีการแจกแจงใกล้เคียงปกติ ไม่ใช่กฎสากลสำหรับข้อมูลทุกชนิด

![ตำแหน่งค่าที่อาจผิดปกติบนการแจกแจงปกติ](assets/zscore_normal_distribution.png)

ในภาพ ค่าบริเวณปลายทั้งสองด้านอยู่ห่างจากค่าเฉลี่ยมากและอาจถูกระบุให้ตรวจสอบด้วย Z-score แต่การตัดสินใจยังต้องพิจารณาสมมติฐานการแจกแจงและบริบทของข้อมูล

# ข้อจำกัดของ Z-score

แม้เราจะสามารถคำนวณ Z-score ให้กับข้อมูลได้ทุกค่า แต่การใช้เกณฑ์ เช่น  
`|z| ≥ 3` เพื่อตรวจหา Potential Outliers อาจไม่เหมาะกับข้อมูลทุกลักษณะ

## 1. ข้อมูลมี Distribution แบบเบ้

Z-score ใช้ Mean และ Standard Deviation เป็นจุดอ้างอิง  
หากข้อมูลมีการกระจายไม่สมมาตร Mean อาจถูกดึงไปทางด้านที่มีค่ามากหรือน้อยเป็นพิเศษ

ตัวอย่างข้อมูลที่มักมี Right-skewed Distribution:

- รายได้
- ยอดซื้อของลูกค้า
- ราคาบ้าน
- ระยะเวลารอ
- จำนวนผู้ติดตามใน Social Media

ในข้อมูลลักษณะนี้ ค่าที่สูงกว่าข้อมูลส่วนใหญ่อาจเป็นค่าที่เกิดขึ้นได้ตามธรรมชาติ แต่ Z-score อาจระบุค่าเหล่านั้นเป็น Potential Outliers จำนวนมาก หรืออาจกำหนดขอบเขตที่ไม่เหมาะสม

ตัวอย่าง: `รายได้: 20,000  22,000  25,000  28,000  30,000  150,000`

ค่า `150,000` อาจเป็นรายได้จริงของพนักงานระดับผู้บริหาร ไม่จำเป็นต้องเป็นข้อมูลผิด เพียงแต่อยู่ในกลุ่มที่พบได้น้อย

## 2. ชุดข้อมูลมีขนาดเล็ก

เมื่อมีข้อมูลจำนวนน้อย Mean และ Standard Deviation อาจเปลี่ยนแปลงมากเมื่อเพิ่มหรือลบข้อมูลเพียงหนึ่งค่า

นอกจากนี้ ข้อมูลขนาดเล็กอาจยังไม่สะท้อน Distribution ที่แท้จริงของประชากร  
จึงไม่ควรใช้เกณฑ์ `|z| ≥ 3` เป็นหลักฐานเพียงอย่างเดียวในการตัดสินว่าเป็น Outlier


## 3. มีค่าที่สูงหรือต่ำมากหลายค่า

Mean และ Standard Deviation มีความไวต่อค่าที่สูงหรือต่ำมาก  
เมื่อมีค่าลักษณะนี้หลายค่า ค่าดังกล่าวอาจดึง Mean และเพิ่ม Standard Deviation ทำให้ขอบเขตของ Z-score กว้างขึ้น

ผลคือค่าที่ควรถูกระบุให้ตรวจสอบอาจมี Z-score ไม่ถึงเกณฑ์ ปัญหานี้เรียกว่า **Masking Effect**

> **Masking Effect**: Outliers หลายค่าดึง Mean และ Standard Deviation จนทำให้ Outliers บางค่าไม่ถูกตรวจพบ

ตัวอย่าง: `10, 11, 12, 13, 14, 60, 65`

ค่า `60` และ `65` ทำให้ทั้ง Mean และ Standard Deviation เพิ่มขึ้น เมื่อคำนวณ Z-score ค่าสองค่านี้จึงอาจดูไม่ห่างจาก Mean มากเท่าที่ควร และ "ช่วยกันซ่อน" ความผิดปกติของกันและกัน

## 4. ข้อมูลประกอบด้วยหลายกลุ่ม

หากข้อมูลมาจากหลายกลุ่มที่มีพฤติกรรมต่างกัน การคำนวณ Mean และ Standard Deviation รวมทุกกลุ่มอาจทำให้ได้จุดอ้างอิงที่ไม่เป็นตัวแทนของกลุ่มใดเลย

ตัวอย่าง:
```
ลูกค้าทั่วไป: ยอดซื้อประมาณ 500–2,000 บาท
ลูกค้าธุรกิจ: ยอดซื้อประมาณ 20,000–100,000 บาท
```

หากนำลูกค้าทั้งสองกลุ่มมาคำนวณ Z-score ร่วมกัน ยอดซื้อของลูกค้าธุรกิจอาจถูกมองว่าผิดปกติ ทั้งที่เป็นพฤติกรรมปกติของกลุ่มนั้น

ดังนั้นควรแยกกลุ่มลูกค้าก่อน แล้วตรวจหา Potential Outliers ภายในแต่ละกลุ่ม

## แนวทางที่อาจเหมาะกว่า

### ใช้ IQR หรือ Robust Statistics

IQR ใช้ Q1, Q3 และ Median ซึ่งได้รับผลกระทบจากค่าที่สูงหรือต่ำมากน้อยกว่า Mean และ Standard Deviation จึงเหมาะกับข้อมูลที่มี Outliers หรือ Distribution แบบเบ้มากกว่า

### Transform ข้อมูล

สำหรับข้อมูลที่เป็นค่าบวกและมี Right-skewed Distribution อาจใช้ Log Transformation เพื่อลดความแตกต่างระหว่างค่าที่สูงมากกับข้อมูลส่วนใหญ่

```python
import numpy as np

df["log_income"] = np.log1p(df["income"])
```
`log1p(x)` คำนวณ `log(1+x)` จึงรองรับค่า `0` ได้ แต่ไม่ควรใช้โดยตรงกับค่าที่น้อยกว่า `-1`


### แยกกลุ่มก่อนตรวจสอบ

หากข้อมูลประกอบด้วยหลายกลุ่ม ควรตรวจหา Potential Outliers ภายในกลุ่มที่มีลักษณะใกล้เคียงกัน เช่น

- แยกลูกค้าทั่วไปออกจากลูกค้าธุรกิจ
- แยกบ้านตามพื้นที่
- แยกคะแนนตามห้องเรียนหรือระดับชั้น


### ใช้ Domain Rules ร่วมด้วย

Statistical Methods แสดงว่าค่าใดแตกต่างจากข้อมูลส่วนใหญ่  
แต่ Domain Rules ช่วยตรวจสอบว่าค่านั้นเป็นไปได้หรือผิดเงื่อนไข

ตัวอย่าง:

- `Final = 78/35` ผิด Domain Rule
- `Final = 35/35` ไม่ผิด Domain Rule แม้อาจแตกต่างจากคะแนนส่วนใหญ่

> **Z-score** เป็น Screening Method ไม่ใช่คำตัดสินสุดท้าย ควรตรวจสอบ Distribution, ขนาดข้อมูล, กลุ่มของข้อมูล และ Domain Rules ก่อนตัดสินใจจัดการค่าที่ตรวจพบค่ะ

# Univariate กับ Multivariate Outlier

## Univariate Outlier

พิจารณาความผิดปกติของ **ตัวแปรเดียว** โดยเปรียบเทียบค่าหนึ่งกับ Distribution ของตัวแปรนั้น

ตัวอย่าง:

- คะแนน Final ของนักศึกษาส่วนใหญ่อยู่ระหว่าง 20–35
- แต่มีค่าหนึ่งเท่ากับ 78
- เมื่อพิจารณาเฉพาะคอลัมน์ Final ค่า 78 แตกต่างจากข้อมูลส่วนใหญ่อย่างชัดเจน

วิธีที่ใช้ เช่น Box Plot, IQR และ Z-score

## Multivariate Outlier

พิจารณา **หลายตัวแปรร่วมกัน**

ค่าในแต่ละตัวแปรอาจไม่ผิดปกติเมื่อพิจารณาแยกกัน  
แต่ Combination ของค่าหลายตัวแปรอาจมีรูปแบบที่แตกต่างจากข้อมูลส่วนใหญ่

วิธีที่ใช้ เช่น Scatter Plot, Isolation Forest และ Local Outlier Factor

> การตรวจแบบหลายตัวแปรควรเลือกเฉพาะตัวแปรที่มีความหมาย และไม่ควรใส่รหัสระเบียนหรือ Identifier ลงไปโดยไม่พิจารณา

| ประเด็น | Univariate Outlier | Multivariate Outlier |
|---|---|---|
| จำนวนตัวแปรที่พิจารณา | ครั้งละหนึ่งตัวแปร | หลายตัวแปรร่วมกัน |
| สิ่งที่ตรวจหา | ค่าที่สูงหรือต่ำผิดปกติ | Combination ที่เกิดขึ้นได้ยาก |
| ตัวอย่าง | Final = 78/35 | Final สูง แต่คะแนนส่วนอื่นต่ำทั้งหมด |
| วิธีพื้นฐาน | Box Plot, IQR, Z-score | Scatter Plot, Isolation Forest |

---

## ตัวอย่าง Multivariate Outlier

พิจารณาคะแนนของนักศึกษาสามคน ซึ่งทุกคะแนนยังอยู่ภายในช่วงที่กำหนด

| Student | HW (30) | Lab (15) | Quiz (25) | Midterm (25) | Final (35) |
|---|---:|---:|---:|---:|---:|
| A | 26 | 14 | 22 | 21 | 32 |
| B | 24 | 13 | 20 | 19 | 30 |
| C | 5 | 4 | 6 | 7 | 34 |

เมื่อพิจารณาทีละตัวแปร คะแนนของ Student C ไม่ได้ผิด Domain Rules:

- HW = 5 อยู่ในช่วง 0–30
- Lab = 4 อยู่ในช่วง 0–15
- Quiz = 6 อยู่ในช่วง 0–25
- Midterm = 7 อยู่ในช่วง 0–25
- Final = 34 อยู่ในช่วง 0–35

แต่เมื่อพิจารณาคะแนนทั้งหมดร่วมกัน Student C มีรูปแบบที่แตกต่างจากนักศึกษาส่วนใหญ่:

> คะแนนระหว่างภาคทุกส่วนค่อนข้างต่ำ แต่คะแนน Final สูงมาก

Combination นี้จึงอาจถูกระบุเป็น **Multivariate Outlier** และควรได้รับการตรวจสอบเพิ่มเติม

### ตัวอย่างโค้ด และ Scatter Plot แสดง Multivariate Outlier
```python
import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt

example = pd.DataFrame({
    "Student": ["A", "B", "C"],
    "Coursework": [83, 76, 22],
    "Final": [32, 30, 34]
})

sns.scatterplot(
    data=example,
    x="Coursework",
    y="Final",
    hue="Student",
    s=150
)

for _, row in example.iterrows():
    plt.text(
        row["Coursework"] + 1,
        row["Final"],
        row["Student"]
    )

plt.title("Example of a Multivariate Outlier")
plt.xlabel("Coursework Score (%)")
plt.ylabel("Final Score")
plt.show()
```
![alt text](assets/multivariate_scatterplot.png)

Student C จะเห็นชัดว่า Final ไม่ได้สูงผิดช่วง แต่ตำแหน่งเมื่อพิจารณาร่วมกับ Coursework แตกต่างจาก A และ B


# จาก Univariate สู่ Multivariate Outlier Detection

วิธีที่เรียนมาก่อนหน้านี้ เช่น Box Plot, IQR และ Z-score ตรวจหา Potential Outliers โดยพิจารณาข้อมูล **ทีละตัวแปร**

อย่างไรก็ตาม ในบางกรณี ค่าแต่ละตัวแปรอาจไม่ผิดปกติเมื่อพิจารณาแยกกัน แต่ Combination ของหลายตัวแปรอาจแตกต่างจากข้อมูลส่วนใหญ่

ตัวอย่างเช่น นักศึกษาคนหนึ่งมีคะแนน HW, Lab, Quiz และ Midterm ค่อนข้างต่ำ แต่มีคะแนน Final สูงมาก แม้คะแนนแต่ละส่วนยังอยู่ในช่วงที่กำหนด แต่รูปแบบคะแนนเมื่อนำมาพิจารณาร่วมกันอาจพบได้น้อย

การตรวจหาความผิดปกติลักษณะนี้เรียกว่า **Multivariate Outlier Detection**

# Isolation Forest

**Isolation Forest** เป็นอัลกอริทึมสำหรับตรวจหา Anomalies ในข้อมูลแบบตาราง (Tabular Data) และข้อมูลที่มีหลายตัวแปร

แนวคิดหลักของ Isolation Forest คือ:

1. สุ่มเลือก Feature หนึ่งตัว
2. สุ่มเลือกค่าที่ใช้แบ่งข้อมูลระหว่างค่าต่ำสุดและสูงสุดของ Feature นั้น
3. แบ่งข้อมูลซ้ำในลักษณะของ Tree จนสามารถแยกแต่ละ Observation ออกจากข้อมูลอื่นได้
4. ทำกระบวนการนี้ซ้ำด้วย Tree หลายต้น จึงเรียกว่า Forest

Observation ที่มีลักษณะคล้ายข้อมูลส่วนใหญ่มักอยู่รวมกันเป็นกลุ่ม จึงต้องแบ่งข้อมูลหลายครั้งกว่าจะแยก Observation นั้นออกมาได้

ในทางตรงกันข้าม Observation ที่แตกต่างจากข้อมูลส่วนใหญ่มักอยู่ห่างจากกลุ่มหลัก จึงสามารถถูกแยกออกได้ด้วยจำนวนครั้งที่น้อยกว่า

จำนวนครั้งที่ใช้แยก Observation เรียกว่า **Path Length**

- Path Length สั้น → มีแนวโน้มเป็น Anomaly
- Path Length ยาว → มีแนวโน้มเป็นข้อมูลทั่วไป



![แนวคิดการแยกข้อมูลของ Isolation Forest](assets/isolation_forest_concept.png)

จากภาพ จุดสีแดงที่อยู่ห่างจากข้อมูลส่วนใหญ่สามารถถูกแยกออกได้ด้วยการแบ่งเพียงไม่กี่ครั้ง จึงมี Path Length สั้น ส่วนจุดที่อยู่รวมกับข้อมูลทั่วไปต้องใช้การแบ่งหลายครั้งกว่าจะแยกออกมาได้

Isolation Forest ไม่ได้พิจารณาผลจาก Tree เพียงต้นเดียว แต่คำนวณ Path Length เฉลี่ยจาก Tree หลายต้น หาก Observation หนึ่งมี Path Length เฉลี่ยสั้นกว่า Observation อื่นอย่างชัดเจน แบบจำลองจะให้ค่า Anomaly Score สูงและอาจระบุ Observation นั้นเป็น Potential Outlier

เมื่อนำไปใช้ใน scikit-learn:

- `predict()` คืนค่า `1` สำหรับ Inlier และ `-1` สำหรับ Potential Outlier
- `decision_function()` ให้คะแนนที่ยิ่งต่ำ ยิ่งมีแนวโน้มเป็น Anomaly
- คะแนนติดลบมักถูกจัดเป็น Potential Outlier ตาม Threshold ของแบบจำลอง


> ⚠️ **ข้อควรระวัง**
>
> - **Outlier Detection:** Training Data อาจมี Outliers ปะปนอยู่ และเราต้องการค้นหาค่าเหล่านั้นภายในข้อมูลชุดเดิม
> - **Novelty Detection:** Training Data ถือว่าเป็นข้อมูลปกติ และเราต้องการตรวจสอบว่า Observation ใหม่แตกต่างจากรูปแบบปกติที่แบบจำลองเรียนรู้ไว้หรือไม่

## การใช้ Isolation Forest

```python

from sklearn.ensemble import IsolationForest

features = ["HW", "Lab", "Quiz", "Midterm", "Final"]    # select only wanted columns

model = IsolationForest(
    n_estimators=100,       # number of tree
    contamination="auto",   # สัดส่วนของ Outliers ที่คาดว่าจะมีอยู่ใน Training Data
    random_state=42         # for demonstration purpose only
)

labels = model.fit_predict(df[features])                # fit and predict
scores = model.decision_function(df[features])          # anomaly score

result = df.assign(
    anomaly_score=scores,
    potential_outlier=(labels == -1)
).sort_values("anomaly_score")                      # display label and anomaly score

result.head(10)
```

- `contamination` คือสัดส่วนของ Outliers ที่คาดว่าจะมีอยู่ใน Training Data  
Isolation Forest ใช้ค่านี้เพื่อกำหนด Threshold สำหรับแบ่ง Observation ออกเป็น Inlier และ Potential Outlier เช่น `contamination=0.05` หมายถึง เราคาดว่าข้อมูลประมาณ 5% มีแนวโน้มเป็น Outliers แบบจำลองจึงกำหนด Threshold เพื่อให้ Observation ที่มี Anomaly Score ต่ำที่สุดประมาณ 5% ถูกจัดเป็น Potential Outliers
> การกำหนด `contamination=0.05` ไม่ได้หมายความว่าข้อมูลผิดจริง 5% แต่เป็น Assumption ที่ผู้วิเคราะห์กำหนดให้แบบจำลองใช้สร้าง Threshold เมื่อใช้ "auto" แบบจำลองจะกำหนด Threshold อัตโนมัติตามหลักการดั้งเดิมของ Isolation Forest โดยไม่บังคับว่าต้องมี Outliers ตามสัดส่วนที่ผู้ใช้ระบุ
- `1` หมายถึงแบบจำลองจัดเป็นข้อมูลทั่วไป (Inlier)
- `-1` หมายถึงแบบจำลองระบุเป็นค่าที่อาจผิดปกติ
- ค่า `anomaly_score` ที่ต่ำกว่าแสดงว่าระเบียนมีความผิดปกติมากกว่า

# เพราะเหตุใดต้องแปลง Categorical Data

Categorical Data บางคอลัมน์ถูกเก็บเป็นข้อความ เช่น

| basket_id | fruit | weight |
|---:|---|---:|

ข้อความอย่าง `apple`, `orange` และ `grape` เหมาะกับการอ่านและทำความเข้าใจ แต่ Machine Learning Algorithms ส่วนใหญ่ไม่สามารถนำข้อความเหล่านี้ไปคำนวณได้โดยตรง

จึงต้องแปลง Categorical Data ให้อยู่ในรูปแบบตัวเลขก่อนนำไปสร้างแบบจำลอง

# ทำไมไม่แทนหมวดหมู่ด้วยตัวเลขโดยตรง

เราอาจแปลงหมวดหมู่เป็นตัวเลขได้ดังนี้

```text
apple  = 1
orange = 2
grape  = 3
```

แต่การแปลงแบบนี้ทำให้ดูเหมือนว่าหมวดหมู่มีลำดับและระยะห่าง:

```text
grape > orange > apple
```

ทั้งที่ชนิดของผลไม้เป็น **Nominal Data** ซึ่งไม่มีลำดับสูงหรือต่ำ

ดังนั้น การแทน Nominal Data ด้วยเลขลำดับอาจทำให้แบบจำลองตีความความสัมพันธ์ที่ไม่มีอยู่จริง

> สำหรับ Nominal Data ที่มีจำนวนหมวดหมู่ไม่มาก วิธีที่ใช้กันทั่วไปคือ **One-hot Encoding**

# One-hot Encoding

One-hot Encoding สร้างคอลัมน์ใหม่สำหรับแต่ละหมวดหมู่

- ค่า `1` หมายถึง ระเบียนนั้นอยู่ในหมวดหมู่นั้น
- ค่า `0` หมายถึง ระเบียนนั้นไม่ได้อยู่ในหมวดหมู่นั้น

ตัวอย่าง:

| fruit | fruit_apple | fruit_grape | fruit_orange |
|---|---:|---:|---:|
| apple | 1 | 0 | 0 |
| orange | 0 | 0 | 1 |
| grape | 0 | 1 | 0 |
| apple | 1 | 0 | 0 |

การเข้ารหัสแบบนี้ไม่กำหนดลำดับให้กับ `apple`, `grape` และ `orange`

---

# สร้างข้อมูลตัวอย่าง

```python
import pandas as pd

df = pd.DataFrame({
    "basket_id": [1, 2, 3, 4],
    "fruit": ["apple", "orange", "grape", "apple"],
    "weight": [1.2, 1.5, 0.8, 1.1]
})

display(df)
```

ผลลัพธ์:

| basket_id | fruit | weight |
|---:|---|---:|
| 1 | apple | 1.2 |
| 2 | orange | 1.5 |
| 3 | grape | 0.8 |
| 4 | apple | 1.1 |

ในตัวอย่างนี้:

- `basket_id` เป็น Identifier
- `fruit` เป็น Nominal Categorical Data
- `weight` เป็น Numerical Data

เราต้องการแปลงเฉพาะคอลัมน์ `fruit` ด้วย One-hot Encoding

---

# `pd.get_dummies()` คืออะไร

`pd.get_dummies()` เป็นฟังก์ชันของ pandas สำหรับแปลง Categorical Data เป็นคอลัมน์แบบ Dummy หรือ Indicator Variables

สามารถแปลงเฉพาะคอลัมน์ `fruit` ได้ดังนี้:

```python
fruit_encoded = pd.get_dummies(
    df["fruit"],
    prefix="fruit",
    dtype=int
)

display(fruit_encoded)
```

ผลลัพธ์:

| fruit_apple | fruit_grape | fruit_orange |
|---:|---:|---:|
| 1 | 0 | 0 |
| 0 | 0 | 1 |
| 0 | 1 | 0 |
| 1 | 0 | 0 |

ความหมายของ Parameters:

- `df["fruit"]` คือคอลัมน์ที่ต้องการแปลง
- `prefix="fruit"` เพิ่มคำว่า `fruit_` หน้าชื่อหมวดหมู่
- `dtype=int` กำหนดให้ผลลัพธ์เป็นเลข `0` และ `1`

---

# แปลง Categorical Column ภายใน DataFrame

เราสามารถให้ `pd.get_dummies()` แปลงคอลัมน์ `fruit` ภายใน DataFrame ได้โดยตรง

```python
df_encoded = pd.get_dummies(
    df,
    columns=["fruit"],
    prefix="fruit",
    dtype=int
)

display(df_encoded)
```

ผลลัพธ์:

| basket_id | weight | fruit_apple | fruit_grape | fruit_orange |
|---:|---:|---:|---:|---:|
| 1 | 1.2 | 1 | 0 | 0 |
| 2 | 1.5 | 0 | 0 | 1 |
| 3 | 0.8 | 0 | 1 | 0 |
| 4 | 1.1 | 1 | 0 | 0 |

สิ่งที่เกิดขึ้น:

1. คอลัมน์ `fruit` ถูกนำออก
2. สร้างคอลัมน์ใหม่หนึ่งคอลัมน์ต่อหนึ่งหมวดหมู่
3. คอลัมน์อื่น เช่น `basket_id` และ `weight` ยังคงอยู่

วิธีนี้ไม่จำเป็นต้องใช้ `pd.concat()` เพื่อรวมข้อมูลด้วยตนเอง

---

# แปลง Categorical Data หลายคอลัมน์

หาก DataFrame มี Categorical Data มากกว่าหนึ่งคอลัมน์ สามารถระบุชื่อคอลัมน์ทั้งหมดใน `columns`

```python
df = pd.DataFrame({
    "fruit": ["apple", "orange", "grape", "apple"],
    "size": ["small", "large", "medium", "small"],
    "weight": [1.2, 1.5, 0.8, 1.1]
})

df_encoded = pd.get_dummies(
    df,
    columns=["fruit", "size"],
    dtype=int
)

display(df_encoded)
```

pandas จะสร้าง One-hot Encoding ให้ทั้ง `fruit` และ `size`

ตัวอย่างคอลัมน์ที่ได้:

```text
weight
fruit_apple
fruit_grape
fruit_orange
size_large
size_medium
size_small
```

---

# ไม่ควรใช้ One-hot Encoding กับทุกคอลัมน์

ก่อนเข้ารหัส ควรพิจารณาความหมายและจำนวนหมวดหมู่ของแต่ละตัวแปร

| ตัวแปร | ควรใช้ One-hot หรือไม่ | เหตุผล |
|---|---|---|
| ประเภทผลไม้ | ควร | เป็น Nominal Data และมีหมวดหมู่น้อย |
| จังหวัด | อาจใช้ได้ | ต้องพิจารณาจำนวนจังหวัดและวัตถุประสงค์ |
| ระดับความเสี่ยง | ไม่ควรใช้ทันที | เป็น Ordinal Data ที่มีลำดับ |
| Student ID | ไม่ควร | เป็น Identifier |
| ชื่อลูกค้า | ไม่ควร | มีหมวดหมู่จำนวนมากและเกือบไม่ซ้ำกัน |
| รหัสสินค้า | ต้องพิจารณา | อาจสร้างคอลัมน์จำนวนมากเกินไป |

One-hot Encoding เหมาะกับ **Nominal Data ที่มีจำนวนหมวดหมู่ไม่มาก**

หากตัวแปรมีหมวดหมู่จำนวนมาก การทำ One-hot Encoding อาจสร้างคอลัมน์จำนวนมากและทำให้ Dataset มีขนาดใหญ่ขึ้น

---

# ข้อจำกัดของ `pd.get_dummies()`

`pd.get_dummies()` เหมาะสำหรับ:

- การสำรวจข้อมูล
- การทำความสะอาดและเตรียมข้อมูลเบื้องต้น
- การสาธิตแนวคิด One-hot Encoding
- Dataset ที่ยังไม่ได้แบ่งเป็น Training และ Test Data

แต่ในงาน Machine Learning หากใช้ `pd.get_dummies()` แยกกับ Training Data และ Test Data อาจได้ชุดคอลัมน์ไม่ตรงกัน เพราะแต่ละชุดอาจพบหมวดหมู่ต่างกัน

ตัวอย่าง:

| Dataset | หมวดหมู่ที่พบ | คอลัมน์ที่สร้าง |
|---|---|---|
| Training Data | apple, orange | apple, orange |
| Test Data | apple, grape | apple, grape |

ประเด็นนี้จะได้รับการจัดการด้วย `OneHotEncoder` และ Machine Learning Pipeline ในบท Machine Learning

> ในบทนี้ เราจะเน้นการเข้าใจแนวคิด One-hot Encoding และการใช้งาน `pd.get_dummies()` ก่อน
